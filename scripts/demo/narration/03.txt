Workflows are graphs. From the Workflows page, the templates drawer offers two shipped pipelines; instantiating the dev pipeline makes an editable copy. In the builder you can see Coder, then Reviewer, then a human gate, then Deployer. The feedback loop is nothing more than an edge from Reviewer back to Coder with a condition on the reviewer's typed verdict; the other edge leads to the gate when the verdict is approved. Each agent node has a task template over the run input and the state so far, and an output schema the agent's result must satisfy. The limits panel bounds the loop. Nothing about Coder or Reviewer is hard-coded in the engine. Validation reports problems on the node or edge they belong to. I'll run it with a small task: a Fibonacci function with tests.
